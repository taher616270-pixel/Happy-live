# حالة لوحة إدارة Happy Live

آخر مراجعة: 2026-11-11

## البنية الفعلية

- الواجهة مستقلة عن Flutter: `frontend/web/admin/index.html` وتُقدَّم من Pages على المسار `/admin/`.
- واجهة المستخدمين الأساسية تبقى في تطبيق Flutter؛ لا يوجد اعتماد على مسار Flutter لعرض لوحة الإدارة.
- الخادم النشط هو Cloudflare Worker في `backend/worker/src/index.ts`، وقاعدة البيانات D1 هي `happy-live-db`.
- Laravel في `backend/` هيكل تاريخي غير نشط. ملف `backend/routes/api.php` يحتوي حاليًا على فحص صحة فقط، و`backend/README.md` يحدد Worker بوصفه الواجهة الخلفية المعتمدة. لذلك يجب عدم إضافة وظائف الإدارة إلى Laravel أو افتراض أن لديه عقودًا تشغيلية.

## المصادقة والصلاحيات الحالية

- حسابات الإدارة وجلساتها منفصلة في `admin_accounts` و`admin_account_roles` و`admin_sessions`، ولا تعتمد على جلسة مستخدم عادي.
- تسجيل الدخول: `POST /api/v1/admin/auth/login`. تُخزَّن تجزئة رمز الجلسة في D1، ومدة جلسة الإدارة 12 ساعة.
- كلمات المرور تستخدم PBKDF2-SHA256 مع salt، بحد أدنى 100,000 دورة.
- حد محاولات تسجيل الدخول المشترك مع المصادقة هو 8 محاولات لكل عنوان IP خلال 15 دقيقة.
- التهيئة الأولى: `GET /api/v1/admin/auth/setup-status` و`POST /api/v1/admin/auth/setup`. تتطلب التهيئة سر Worker باسم `ADMIN_SETUP_TOKEN` وكلمة مرور من 12 حرفًا على الأقل، وتُسمح مرة واحدة.
- حالة قاعدة الإنتاج عند المراجعة: اكتملت تهيئة المالك، ويوجد حساب إداري نشط واحد باسم `owner`. لا تُخزَّن كلمة المرور في المستودع ولا يمكن استرجاعها من التجزئة. لا توجد حاليًا نقطة API لإعادة تعيين كلمة مرور المدير؛ لا تخمّن كلمة مرور ولا تنفذ إعادة ضبط مباشرة على قاعدة الإنتاج.
- الخادم يستخرج دور المدير من سجل D1 المرتبط برمز الجلسة. لا يثق في حقل role يرسله المتصفح.
- الصلاحيات المعرفة في Worker:
  - `owner`: جميع الصلاحيات.
  - `admin`: قراءة لوحة المعلومات والمستخدمين والغرف وسجل التدقيق، وإدارة حالة المستخدمين وطرد الجلسات والغرف وإدارة مشرفي الغرف والحظر والطرد والكتم وقراءة/إدارة إعداد Agora.
  - `moderator`: قراءة لوحة المعلومات والمستخدمين والغرف وسجل التدقيق فقط.
  - إدارة أدوار مشرفي التطبيق محصورة بالمالك حاليًا.
- واجهات الجلسة: `GET /api/v1/admin/me` و`POST /api/v1/admin/auth/logout`.

## الوظائف المربوطة بعقود حقيقية

| القسم | نقاط API | الحالة |
|---|---|---|
| الرئيسية | `GET /api/v1/admin/overview` | مربوط بإحصاءات D1 الحقيقية |
| الإحصائيات | `GET /api/v1/admin/stats` | مربوط بأعداد المستخدمين والغرف والمنشورات والرسائل |
| المستخدمون | `GET /api/v1/admin/users` | بحث وقائمة حقيقية |
| حظر/رفع حظر المستخدم | `PATCH /api/v1/admin/users/:id/status` | يغيّر حالة الحساب إلى suspended/active، ويلغي الجلسات ويزيله من مقاعد الغرف عند التعليق |
| طرد المستخدم | `POST /api/v1/admin/users/:id/kick` | يلغي الجلسات الحالية فقط؛ لا يمنع تسجيل الدخول مجددًا |
| الغرف | `GET /api/v1/admin/rooms` و`PATCH /api/v1/admin/rooms/:id/status` | عرض الغرف وفتحها/إغلاقها |
| مشرفو التطبيق | `GET /api/v1/admin/moderators` و`PATCH /api/v1/admin/users/:id/role` | تعيين/إزالة دور admin أو moderator لمستخدم نشط؛ المالك فقط |
| سجل التدقيق | `GET /api/v1/admin/audit` | يعرض الإجراءات المسجلة في D1 |
| إدارة الغرفة | `GET /api/v1/admin/rooms/:id/moderation` و`POST /api/v1/admin/rooms/:id/moderation` | عرض مقاعد المايك النشطة ومشرفي الغرفة والحظر والطرد؛ تعيين/إزالة مشرف، كتم/إلغاء كتم، طرد لمدة 60 ثانية، حظر دائم ورفع الحظر. الكتابة تتطلب `rooms.moderate` من الخادم. |
| Agora | `GET /api/v1/admin/agora/status` و`PATCH /api/v1/admin/agora/voice` | حالة الخدمة والتحكم العام بالصوت من الخادم |

كل عمليات التعديل أعلاه تتحقق من جلسة الإدارة والصلاحية داخل Worker. لا تُجرى استعلامات D1 من المتصفح. إجراءات الغرف تُسجل باسم المدير الفعلي (`adminId` و`adminUsername`) داخل سجل التدقيق. ولأن أعمدة `assigned_by` و`banned_by` و`kicked_by` و`muted_by` القديمة مرتبطة بمفاتيح مستخدمي التطبيق، تستخدم واجهة الإدارة مالك الغرفة كقيمة توافقية لهذه الأعمدة فقط؛ سجل التدقيق هو المرجع لهوية المدير المنفذ.

## الفجوات التي تمنع إكمال بقية الأقسام

1. **VIP والشحن الإلكتروني والهدايا:** لا توجد في مخطط D1 جداول أو نقاط API لعضويات VIP أو بوابة شحن أو كتالوج/سجل إرسال هدايا. المحفظة ليست ضمن هذه الفجوة: توجد جداول `user_wallets` و`wallet_transactions`، وواجهة `GET /api/v1/admin/wallets` تعرض الأرصدة وسجل الحركات، كما يتيح `POST /api/v1/admin/users/:id/wallet/credit` إضافة يدوية للمالك فقط. أنواع الحركات الحالية تشمل `room_upgrade` و`admin_credit`؛ هذا لا يعني وجود بوابة دفع أو شحن إلكتروني.
2. **تفاصيل العقوبات داخل الغرف:** أصبحت واجهة الإدارة متصلة بالجداول الموجودة عبر `GET/POST /admin/rooms/:id/moderation`. الطرد المؤقت 60 ثانية، والحظر دائم حتى رفعه، والسبب الاختياري يُحفظ في سجل التدقيق. لا يوجد حتى الآن حقل سبب أو مدة انتهاء داخل سجل الحظر نفسه، كما أن عرض الأعضاء النشطين يقتصر على مقاعد المايك؛ البحث يتيح الوصول إلى أي حساب نشط. أعمدة الإسناد القديمة ما زالت تستخدم مفاتيح مستخدمي التطبيق كما هو موضح أعلاه.
3. **إدارة حسابات مديري اللوحة:** أُضيفت في هذا الفرع واجهات مالك فقط (`GET/POST /api/v1/admin/accounts` و`PATCH /api/v1/admin/accounts/:id/role|status` و`POST /api/v1/admin/accounts/:id/password|revoke-sessions`). الخادم يتحقق من دور المالك من جلسة D1، يحمي حساب المالك، ويلغي الجلسات عند التعطيل أو تدوير كلمة المرور. هذه التغييرات لم تُدمج أو تُنشر بعد.
4. **ربط هوية المدير في سجل التدقيق:** أُضيفت في هذا الفرع migration `0026_admin_audit_actor_refs.sql` وجدول ربط علائقي بين سجل التدقيق وحساب الإدارة. تستخدم عمليات إدارة حسابات المدير الجديدة مساعدًا يكتب سجل الإجراء والرابط العلائقي في دفعة D1 واحدة، وتقرأ واجهة السجل الهوية من الرابط مع الرجوع إلى `details_json` للسجلات القديمة. migration لم تُطبق على الإنتاج بعد.

تبقى صفحات VIP والشحن والهدايا غير مفعّلة وتوضح غياب عقودها بدل عرض بيانات تجريبية؛ صفحة المحافظ مستقلة ومربوطة بالجداول الفعلية المذكورة أعلاه.
